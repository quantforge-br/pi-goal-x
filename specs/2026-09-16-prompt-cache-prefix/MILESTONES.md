# Implementation log

## 2026-11-11: request-only live tail under explicit markers

- Evidence: one 139-request Anthropic session (Pi 1.5.2, 1h cache writes) with a context-compression proxy that records every request. Its ledger attributed six misses to a client-side mid-history rewrite. Four landed 27–29 requests apart and re-wrote 31k–89k tokens each; before each one, 29–31 retained tails (`Goal snapshot:` counters plus a few task snapshots) had vanished from the resent history at once: the 32-tail overflow reset. The other two followed a pause and a resume (policy `Status:` change) and re-wrote 45k tokens each.
- Cause: counters include elapsed time and tokens, so they differ on every request and each difference retained one tail. The "at most one prefix break per 32 state changes" bound therefore meant one break per ~30 requests. Policy changes reset retention by design.
- First attempt (released as 0.35.2): keep only counters request-only under explicit markers. It removed the overflow resets but left the policy and task snapshots retained. Setback found afterwards: with no periodic reset the policy keeps its first anchor, so a pause/resume re-writes the whole conversation after it instead of the last ~30 requests, and 16 KiB of task snapshots still reset. A real-serializer test that pauses every tenth request fails on 0.35.2 at request 9.
- Fix: under explicit markers the whole live tail (policy, task snapshot, counters) is request-only. Detection is the relocation result in before_provider_request. Implicit-cache sessions are untouched.
- Rejected: raising the tail/byte bounds (only delays the reset and grows the wire), coarser counters (still resets, loses information), deciding by `ctx.model.api` (misses Anthropic-format Chat Completions adapters), and appending a new policy while leaving the old one in history (stale objectives and cancelled scheduling instructions would linger).
- Trade-off accepted: the tail is billed on every request instead of being read from cache. In the measured session it was about 1.9k tokens with a 32-task list; a live run without tasks measured about 0.7k. Retaining the policy is cheaper while policy changes are rare (one pause/resume cycle costs one or two full conversation re-writes; the request-only tail costs about the same as one cycle per ~50–300 requests at 50k–140k context), but it has no upper bound per change and loses the policy under wire-level compression.
- Tests: LiveTailRetention cases (1,000 requests with counter, task and policy churn and no live block inside history, retry, policy change, late marker, dropped blocks, cleared session), handler-level cases in goal-scheduler.test.ts including a pause on every tenth request, and a real-serializer hook chain of 80 requests with pause/resume for Anthropic Messages and Anthropic-format Chat Completions in prompt-cache-sdk-worker.ts. One existing handler test sent a marked payload and asserted the retained layout; it now asserts the request-only layout, and a new case covers the unmarked layout.
- Gates repaired, all failing before this work: context:gate rejected the task-snapshot tail added in 0.35.1 and its baseline predated it (re-measured as `879d5c1-goal-task-snapshot-tail`; no semantic count changed, sizes grew 19 chars without tasks and 143–144 with them); context:cache-gate hashed the package name into the dependency digest, which the fork rename changed, and compared against upstream 0.34.0 although 0.35.1 intentionally changed payloads (identity excluded, pin moved to the fork, driver now runs the registered provider hook); the package check assumed the npm <12 `pack --json` array; the test manifest missed goal-task-snapshot-retention. The controls walkthrough also read atomic-write temp files that could be renamed away first (one ENOENT in three full runs); it now reads only `.md` goal files.
- Live check against the real provider (`pi --mode rpc`, claude-haiku-5-5 through an Anthropic-compatible gateway, 48 requests per run, one interrupt and resume at request 38, a goal without tasks making one small bash call per turn). 0.35.1 lost the prefix at request 32 in both chains: cache read fell from 23.1k to 5.2k tokens with only this extension loaded, and from 34.1k to 9.8k with a context-compression extension also loaded. The request-only tail had no miss in either chain, pause and resume included. The tail cost 784 uncached input tokens per request in the compression chain and about 700 cache-write tokens per request in the bare chain, where the gateway adds a trailing breakpoint. After warm-up the compression chain went from 4.6k input + 29.8k cache-write tokens to 35.6k input + 5.6k cache-write tokens. In the bare chain, with turns this small (about 100 tokens of growth per request), the request-only tail wrote more than the single reset it avoided (36.2k against 23.1k cache-write tokens); the trade reverses once a turn adds more than the tail.
- Validation: `npm run check`, `npm run lint` and `git diff --check` pass. `node scripts/ci-checks.mjs` passes all eight checks under an isolated HOME: 1,327 tests across 98 files with the runner self-check, controls and lifecycle walkthroughs, installed-package check, context gate, provider cross-check, cache gate and retention check.
